UmaTools audit remediation

13 October 2026 · Local implementation and validation. Changes are uncommitted and have not been deployed.

The 13 findings in the original audit have corresponding fixes. Original audit evidence is preserved; it describes the pre-fix checkout.

Additional correctness and optimization work

  • A shared skill repository deduplicates requests and CSV parsing across calculator, optimizer and skills. Server-specific compact master catalogs override matching ratings and costs while retaining community metadata and fallback values.
  • Server reloads are serialized. Costs and ratings both reload, and a browser fixture confirms that the same skill receives a different server's cost.
  • Single-precision aptitude products fix Studious at G to 60. Calculator row scores now refresh when aptitude settings change.
  • The optimizer defers full metadata until needed, preloads critical startup resources, and uses compressed CSV responses. The skill library starts independent downloads together.
  • Runtime service-worker caches are bounded to 100 entries/32 MiB, with an 8 MiB per-response cap. Cache writes extend event lifetime; failed precache installation cannot replace the previous worker. Offline clean-URL navigation has a browser regression test.
  • OCR loader failures can be retried. Lightweight deployment security headers were added.
  • Refreshed community data contains 1,921 skills. Global and JP master snapshots remain separate (732 and 2,194 skill records respectively).

Validation

  • npm run check: passed, including 10 API tests, 4 downloader tests, scoring/solver regressions, 22 data files/manifests, 536 static references and 25 page routes.
  • npm run build: passed; generated compact catalogs, API assets, guide output and 10 new WebP companions.
  • npm run test:browser: passed injection, malformed URL, search ordering/repeat, keyboard focus, Studious G=60, server-switch costs and offline navigation cases.
  • npm run audit:responsive: 94/94 passed. The heuristic iOS compatibility check passed with its existing requestIdleCallback warning; a fallback is present. This is not testing on a physical iOS device.
  • Focused mobile optimizer Lighthouse 13.5 run: performance 98, accessibility/best practices/SEO 100, TTI 2,972 ms, CLS 0.000. This is one local throttled lab result, close to the 3,000 ms target; it is not a field-performance guarantee or a directly controlled comparison with the older Lighthouse version used in the original audit.
  • JavaScript lint has zero errors and 18 existing unused-code warnings. Python lint passes. Dependency audits reported zero known vulnerabilities.

Remaining evidence limits

An automatic JP manifest/database source is still unverified, so JP updates require a local import. The Global community version feed can lag the game. Matching master records improve values but do not supply missing community metadata for every master-only skill. The exact game's midpoint rounding rule still needs a game-backed fixture: float32 products are implemented, while the existing half-up rule is retained (95 × 0.7 currently gives 67). No claim of exhaustive game-mechanic parity is made.

Broader controller extraction, additional payload splitting and API indexing remain optional follow-ups; no measured API bottleneck justified new infrastructure. The fixes retain the existing static-site architecture.
